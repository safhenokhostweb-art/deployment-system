# راهنمای One-Click Deployment

این سند برای توسعه‌دهنده یا مدیری نوشته شده که می‌خواهد از ذخیره یک فایل در VS Code تا دیده‌شدن آن روی سرور واقعی، بدون اجرای هیچ دستور دستی Git، به این سیستم اعتماد کند. مسیر کامل:

```
Developer Machine (Windows)
        |
        | Save File در VS Code
        ↓
Local Agent
        |
        ↓
Deployment Panel
        |
        | Click Publish
        ↓
GitHub Repository
        |
        | Webhook
        ↓
Deployment System
        |
        ↓
Production Server
```

## ۱) نصب اولیه

پیش از نصب، این موارد را روی سیستم توسعه‌دهنده بررسی کنید:

- **PHP** در PATH نصب باشد.
- **Git** در PATH نصب باشد.
- یک **کلید SSH** در `%USERPROFILE%\.ssh` وجود داشته باشد (یا Repository شما از HTTPS با Credential Manager استفاده کند).
- پوشه پروژه از قبل یک **Git Repository واقعی** باشد و remote آن (معمولاً `origin`) درست تنظیم شده باشد.

راحت‌ترین راه شروع، صفحه **راه‌اندازی Deployment Machine** (`/local-agents/setup`) در پنل است — این صفحه دقیقاً همین ۶ مرحله (پیش‌نیاز → نصب → ثبت‌نام → تایید → اتصال پروژه → تست Publish) را به‌ترتیب نشان می‌دهد و در پایین صفحه، وضعیت **READY FOR ONE CLICK DEPLOYMENT** را وقتی همه‌چیز واقعاً آماده باشد نشان می‌دهد.

### نصب دستی (خلاصه)

۱. در پنل، از صفحه راه‌اندازی یا صفحه «کارگزارهای محلی»، **«ساخت توکن ثبت‌نام»** را بزنید. یک `registration_id`، یک `registration_token`، و یک دستور `install.ps1` آماده کپی نمایش داده می‌شود — این مقادیر فقط همان یک‌بار قابل مشاهده‌اند.

۲. آن دستور را در یک PowerShell با دسترسی **Administrator**، داخل پوشه بسته نصب (`deployment-local-agent`)، روی سیستم توسعه‌دهنده اجرا کنید:

```powershell
.\install.ps1 -HubUrl https://your-hub.example -RegistrationId <registration_id> -RegistrationToken <registration_token>
```

این اسکریپت به‌صورت خودکار: PHP/Git/کلید SSH را بررسی می‌کند، فایل‌های Agent را در `C:\ProgramData\DeploymentLocalAgent` کپی می‌کند، در Hub ثبت‌نام می‌کند (بدون هیچ اقدام دستی جداگانه‌ای)، یک Task Scheduler برای اجرای خودکار Agent هنگام ورود به ویندوز می‌سازد، و آن را همین حالا اجرا می‌کند.

۳. به پنل برگردید (**کارگزارهای محلی → تاییدهای در انتظار**) و این Agent را تایید کنید. مقادیر `agent_token` و `signing_secret` فقط همین یک‌بار نمایش داده می‌شوند.

۴. این دو مقدار را در `C:\ProgramData\DeploymentLocalAgent\agent\config.php` جایگزین کنید.

۵. در پنل، وضعیت این Agent باید ظرف حداکثر یک دور Poll به **آنلاین** تغییر کند.

## ۲) اتصال Agent به یک پروژه

از صفحه همان Local Agent، یک **Project Mapping** اضافه کنید: پروژه موردنظر، مسیر محلی آن روی سیستم توسعه‌دهنده (مثلاً `C:\laragon\www\my-project`)، شاخه (`main`)، و نام remote (`origin`). از این پس دکمه **«انتشار تغییرات»** روی صفحه آن پروژه فعال می‌شود.

**حالت انتشار (Deployment Mode)** برای هر نگاشت قابل تنظیم است:
- **دستی**: فقط با کلیک روی «انتشار تغییرات» منتشر می‌شود.
- **با تایید**: به‌محض تشخیص تغییر، یک اعلان می‌آید و با یک کلیک تایید می‌شود.
- **خودکار**: بعد از چند دقیقه پایداری (بدون تغییر بیشتر)، بدون نیاز به تایید منتشر می‌شود.

## ۳) انتشار تغییرات (روزمره)

۱. فایل را در VS Code تغییر دهید و **Save** کنید.
۲. Agent در دور Poll بعدی (پیش‌فرض هر ۱۵ ثانیه) این تغییر را تشخیص می‌دهد.
۳. بسته به Deployment Mode، یا منتظر کلیک دستی می‌مانید یا یک اعلان می‌بینید.
۴. روی صفحه پروژه یا صفحه اعلان، **فایل‌های تغییریافته** را ببینید. اگر فایلی حساس باشد (مثل `.env`، credential، یا token)، در بخش جداگانه **«فایل‌های مسدودشده»** نمایش داده می‌شود — این فایل‌ها **هرگز** commit نمی‌شوند، صرف‌نظر از اینکه چه تنظیماتی دارید.
۵. پیام Commit را (در صورت نیاز) ویرایش کنید و **«تایید انتشار»** را بزنید.
۶. Agent در دور Poll بعدی، `git add`، `git commit`، و `git push` را واقعاً روی سیستم شما اجرا می‌کند — بدون این‌که شما دستوری تایپ کنید.
۷. پس از موفقیت، همان صفحه Commit Hash نهایی را نشان می‌دهد، و به‌محض این‌که Webhook گیت‌هاب یک Deployment جدید بسازد، وضعیت آن (**«وضعیت گیت‌هاب و استقرار»**) هم در همان صفحه ظاهر می‌شود — با لینک به جزئیات کامل استقرار (شامل وضعیت هر سرور).

## ۴) Rollback

- **از صفحه پروژه**: دکمه «بازگشت آخرین انتشار» آخرین commit را با یک commit جدید (`git revert`) برمی‌گرداند — هرگز history را rewrite نمی‌کند.
- **از صفحه «تاریخچه انتشار»** (`/publish-history`): همین دکمه برای آخرین انتشار موفق هر پروژه در دسترس است.
- **اگر خود مرحله Deploy روی سرور شکست بخورد** (نه مرحله Publish): از صفحه جزئیات آن Deployment، دکمه Rollback مخصوص همان استقرار در دسترس است — این کاملاً مستقل از Local Agent است.

## ۵) رفع خطاها

### Git Push شکست خورد

صفحه وضعیت انتشار، پیام خطای واقعی Git را نشان می‌دهد (مثلاً rejected non-fast-forward، یا خطای شبکه). دکمه **«تلاش مجدد»** فقط برای شکست‌های موقتی (قطعی شبکه، قفل موقت remote) مناسب است — دوباره همان commit را push می‌کند، بدون این‌که چیزی را دوباره commit کند (اگر commit قبلاً موفق شده باشد). اگر remote واقعاً از حالت local جلوتر رفته باشد (تغییری مستقل روی همان branch)، این سیستم عمداً آن را خودکار merge/rebase نمی‌کند — این مورد نیاز به بررسی دستی شما دارد، دقیقاً همان‌طور که `SafetyChecker` هرگز اجازه commit روی یک conflict یا merge نیمه‌کاره را نمی‌دهد.

### Local Agent آفلاین است

روی صفحه پروژه یا صفحه انتشار، وضعیت **آفلاین** و زمان **آخرین ضربان (heartbeat)** آن Agent نمایش داده می‌شود. اگر Agent بیش از چند دقیقه آفلاین بماند:
1. مطمئن شوید سیستم توسعه‌دهنده روشن و به اینترنت متصل است.
2. از صفحه آن Local Agent، **«دریافت Log»** را بزنید تا آخرین خروجی واقعی Agent را ببینید.
3. در صورت نیاز، **«راه‌اندازی مجدد»** را بزنید — این یک درخواست Restart در صف Agent قرار می‌دهد که در اولین Poll بعدی اجرا می‌شود.
4. اگر Agent اصلاً هرگز آنلاین نشده، Task Scheduler را روی سیستم توسعه‌دهنده بررسی کنید (Task با نام `DeploymentLocalAgent`) یا `install.ps1` را دوباره اجرا کنید.

### Deployment شکست خورد

صفحه جزئیات آن Deployment، دقیقاً مرحله‌ای که شکست خورده (Current Step) و پیام خطا را نشان می‌دهد. دکمه Rollback مخصوص همان صفحه برای بازگشت سریع به آخرین نسخه سالم در دسترس است.

## ۶) امنیت

- هیچ Secret به‌صورت خام (plaintext) در دیتابیس ذخیره نمی‌شود — `agent_token` هش می‌شود، `signing_secret`/`registration_token`/Webhook Secret با رمزنگاری Laravel (`encrypted`) ذخیره می‌شوند.
- خروجی هر عملیات (Publish/Restart/Operation) پیش از ذخیره در دیتابیس از یک فیلتر Redaction عبور می‌کند که الگوهای `token`/`secret`/`password`/کلیدهای GitHub و AWS را با `[REDACTED]` جایگزین می‌کند.
- فایل‌های حساس (`.env`، `.env.*`، `*.pem`، `*.key`، `credentials.json`، `*.token`) هرگز — حتی بدون تنظیم دستی — توسط Agent کشف یا commit نمی‌شوند.
- Agent هرگز رمز عبور یا توکن گیت‌هاب شما را ذخیره نمی‌کند — فقط از همان تنظیمات SSH/Credential Manager موجود روی سیستم شما برای `git push` استفاده می‌کند.
